New User Account Provisioning

How to create a user account for a new employee or contractor on Example Corp's Linux servers and Windows Active Directory domain.

1. Purpose

This procedure makes sure every new account is approved, created consistently, given only the access the person needs, and recorded. It implements the Password & Authentication Policy (POL-SEC-002) and the Access Control Policy (POL-SEC-003).

2. Scope

  • In scope: standard user accounts for employees and contractors on Linux servers (Ubuntu Server 24.04 LTS) and the Windows Active Directory domain corp.example.com.
  • Out of scope: administrator accounts and service accounts. These need separate approval from the IT Manager (SOP-ACC-004).

3. Roles and responsibilities

RoleResponsibility
HRConfirms employment and start date; opens the new-hire request.
Department headApproves which systems and groups the person needs.
System administratorCreates the account by following this SOP and records the work in the ticket.
Service deskGives the user their temporary password and helps with first login.

4. Prerequisites

Do not start until all of these are true:

  • There is an approved access request ticket (e.g. REQ-2026-0311) listing the required groups.
  • HR has confirmed the employment and start date.
  • The user has accepted the Acceptable Use Policy.
  • You are logged in with your own admin account, not a shared or root account.
  • You know the username, which follows the naming convention: first initial + surname, in lowercase (e.g. Juan Dela Cruz → jdelacruz).

Danger

Never add a user to an administrator group (sudo, Domain Admins) under this SOP. Administrator access needs separate written approval from the IT Manager.

5. Procedure

Choose the platform. The tabs remember your choice, and the verification section below switches with them.

  1. Connect to the server with your personal admin account. 
    ssh your-admin-user@srv-01.corp.example.com
  2. Check that the username is not already taken. 
    id jdelacruz
    Expected output: id: 'jdelacruz': no such user
  3. Create the account with a home directory and the Bash shell. 
    sudo useradd -m -s /bin/bash -c "Juan Dela Cruz" jdelacruz
  4. Set a temporary password and force a change at first login. 
    sudo passwd jdelacruz      # enter a temporary password (12+ characters)
sudo chage -d 0 jdelacruz  # user must change it at first login
  5. Add the user to the groups approved in the ticket. 
    sudo usermod -aG developers jdelacruz

    Warning

    Always use -aG (append). Using -G alone removes the user from every group not listed.

  1. Open PowerShell with your admin account on a management workstation and load the AD module. 
    Import-Module ActiveDirectory
  2. Check that the username is not already taken. 
    Get-ADUser -Filter "SamAccountName -eq 'jdelacruz'"
    Expected: no output.
  3. Create the account in the Staff organizational unit. 
    New-ADUser -Name "Juan Dela Cruz" -GivenName "Juan" -Surname "Dela Cruz" `
  -SamAccountName "jdelacruz" -UserPrincipalName "jdelacruz@corp.example.com" `
  -Path "OU=Staff,DC=corp,DC=example,DC=com" `
  -AccountPassword (Read-Host -AsSecureString "Temporary password") `
  -ChangePasswordAtLogon $true -Enabled $true
  4. Add the user to the groups approved in the ticket. 
    Add-ADGroupMember -Identity "Developers" -Members "jdelacruz"

Hand over the account (both platforms)

  1. Give the temporary password through a separate channel.Tell the user in person, or have the service desk send it by SMS.
  2. Help the user enrol in MFA at first login.Required by POL-SEC-002 for email and VPN.
  3. Record the work in the ticket.Note the username, groups added, date and your name, then close the ticket.

Warning

Never send the username and temporary password together in the same email or chat message.

6. Verification

id jdelacruz
sudo chage -l jdelacruz | head -n 1

Expected output (the IDs may differ):

uid=1005(jdelacruz) gid=1005(jdelacruz) groups=1005(jdelacruz),1002(developers)
Last password change                                    : password must be changed
Get-ADUser jdelacruz -Properties MemberOf, PasswordLastSet |
  Select-Object Name, Enabled, PasswordLastSet, MemberOf

Expected: Enabled is True, PasswordLastSet is empty (the password must be changed at logon), and MemberOf lists only the approved groups.

7. Troubleshooting

ProblemLikely causeSolution
useradd: user 'jdelacruz' already existsThe username is taken, possibly by a former employee.Use the next variation (e.g. jdelacruz2). Never reuse a former employee's account.
usermod: group 'developers' does not existTypo, or the group has not been created.List groups with getent group and confirm the name in the ticket.
“The password does not meet the length, complexity, or history requirement”The temporary password breaks the domain password policy.Use a temporary password of 12 or more characters.
“Access is denied” in PowerShellPowerShell is not running under your admin account.Start PowerShell with Run as different user and use your admin account.
User cannot log in over SSHThe user's group is not allowed in the SSH configuration.Check AllowGroups in /etc/ssh/sshd_config; ask for approval before changing it.

8. Rollback

If an account was created by mistake, disable it, don't delete it. That keeps an audit trail. Then follow the deprovisioning SOP (SOP-ACC-002).

sudo usermod --lock --expiredate 1 jdelacruz   # lock the password and expire the account
Disable-ADAccount -Identity jdelacruz
