Description and reason

Apply all pending Ubuntu security updates, including kernel and OpenSSL packages, to both web servers. The October Ubuntu Security Notices include fixes rated High. The Patch Management Policy requires High-severity patches to be applied within 30 days.

If we don't make this change: the servers stay exposed to known vulnerabilities and we fall out of compliance with the patch policy.

Risk and impact assessment

The website runs on two servers behind a load balancer (lb-01). Patching one server at a time means no downtime is expected, only reduced capacity for about 20 minutes per server.

Pre-implementation checklist

Complete before the window opens

Implementation plan

Do web-01 first. Repeat steps 1–7 for web-02 only after web-01 passes verification.

  1. Drain web-01 in the load balancerso it stops receiving new visitors. Wait until active connections reach 0.
  2. Take a VM snapshotnamed pre-CHG-2026-0088.
  3. Refresh the package list and save the list of updates to this change record. 
    sudo apt update
apt list --upgradable 2>/dev/null | tee ~/CHG-2026-0088-web-01.txt
  4. Install the updates. 
    sudo apt upgrade -y
  5. Reboot if required. 
    [ -f /var/run/reboot-required ] && sudo reboot
  6. Verify the server(see verification below).
  7. Return web-01 to the load balancer pooland watch error rates for 10 minutes.

Verification

systemctl is-active nginx                  # expected: active
curl -sI http://localhost | head -n 1      # expected: HTTP/1.1 200 OK
uname -r                                   # expected: the new kernel version

Then open https://www.example.com from an outside network and check the home page and login page.

Backout plan

If verification fails and cannot be fixed within 15 minutes:

  1. Keep the server out of the load balancer pool.
  2. Revert the VM to the snapshotpre-CHG-2026-0088 (about 10 minutes).
  3. Verify the serverwith the same checks, then return it to the pool.
  4. Record what happenedin this change record. Open an incident if users were affected.

Note

Delete the snapshot 7 days after a successful change. Old snapshots waste storage and slow down the VM.
